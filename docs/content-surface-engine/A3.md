## Architectural invariants (preserved)

- ContentDocument stays generic: `identity.contentType: z.string().min(1)` (OPEN_STRING).
- No universal article assumptions in the core contract. Article-quality rules are OPT-IN
  via a `textos.article@1` CONTENT_PASS profile — never a schema constraint.
- Article/page/entry are NOT introduced as literals in the shared vocabulary.
- Native seam untouched. `PA_NATIVE_SEAM_TOUCHED=NO`.

## Modules added

- `lib/content-surface-engine/conformance/corpus-loader.ts` — loads the 12 migrated
  ContentDocuments from `content/managed-corpus/*.json` and validates each through
  `ContentDocumentSchema`.
- `lib/content-surface-engine/conformance/content-pass.ts` — CONTENT_PASS with two profiles:
  `default` (universal minimums only) and `textos.article@1` (opt-in article rules).
- `lib/content-surface-engine/link-graph/link-graph.ts` — deterministic scoring
  (topic/capability/claim/evidence Jaccard + audience/funnel bonus + explicit-relation
  boost + cannibalization penalty). Filters candidates by `indexableIds` so public links
  can never target a draft.
- `lib/content-surface-engine/lifecycle/lifecycle.ts` — `CURRENT / SOURCE_CHANGED /
  MATURITY_CHANGED / NEEDS_REVIEW` derived from `sourceEvidenceDigest`, `sourceSha`,
  `sourceStatus`, `lastReviewedAt`. Never invents traffic/ranking/engagement signals.
- `lib/content-surface-engine/publication/publication-pass.ts` — fail-closed publication
  authority gate.
- `lib/content-surface-engine/publication/indexable.ts` — the final `INDEXABLE = CONTENT_PASS
  AND SURFACE_PASS AND PUBLICATION_PASS` decision with machine-readable reasons.
- `lib/content-surface-engine/receipt/receipt.ts` — `ReferencePublicationReceipt` factory
  that returns `NOT_ISSUED` with enumerated reasons when authoritative deploy/build context
  is absent. Never fabricates `deploymentId`, `mergeSha`, `canonicalUrl`, or `publishedAt`.

## Authority heuristic audit (phase 3)

Before A3: `product_article`, `developer_note`, `faq_entry` were all auto-mapped to
`schema.org/Article`. Two of those mappings are not factually justified — the shared block
vocabulary does not carry FAQ Q/A pairs (so FAQPage would be an SEO tactic), and
`developer_note` has no author/date guarantees. A3 narrows the default heuristic:

- `product_article` → `Article` (justified: long-form editorial artefact).
- everything else → `null` (no automatic mapping).

Producers may still opt in via `document.seo.schemaType`. `FAQPage` / `HowTo` are never
emitted from the current vocabulary.

## Corpus migration

- Source: 12 markdown insights on `feat/ctc-article-system-1` (READ-ONLY reference).
- Output: 12 JSON ContentDocuments under `content/managed-corpus/*.json` + an
  `INVENTORY.json` recording each source path and its `sha256`. The migration script
  (`scripts/a3-migrate-corpus.ts`) is a ONE-SHOT tool — markdown never becomes a runtime
  authoring source.
- Provenance: the source frontmatters declare `productSnapshotSha =
  d1b8b50552e1b42768a6bd0c0515675e139780d3`, which is NOT present in
  `content/certified-lineage.json`. The migrated documents therefore leave `sourceSha`
  undefined and carry `sourceEvidenceDigest` (sha256 of the source .md file) as evidence.
  `sourceAuthority` stays `UNCERTIFIED`.
- Publication authority preserved: every migrated document is a draft. No escalation.
- See `docs/content-surface-engine/A3-MIGRATION-MATRIX.md` and
  `content/managed-corpus/A3-REPORT.json` for the full deterministic report.

## 12/12 pipeline result

Every migrated insight runs through:

```
ContentDocument → resolveContentSurface(reference, textos-site@1) → RenderReferenceBody
  → CONTENT_PASS(textos.article@1) → evaluateLifecycle → PUBLICATION_PASS → INDEXABLE
```

Deterministic outcome: **12/12 noindex**. Every RED reason is enumerated in the report
(`publication-pass-failed: publication-status-not-publishable` on every document, plus
`content-pass-failed` for docs missing headings/canonical/date fields, plus lifecycle notes).
Nothing is silently indexed.

## LinkGraph + BACKLINK_UPDATE_CANDIDATES

- The LinkGraph is REPORT ONLY. `computeBacklinkCandidates` produces reciprocal-update
  suggestions the caller reviews manually.
- Filtered by `indexableIds`: with the current corpus (no indexable target) the report
  contains zero related items for public consumers — public links can never point at draft
  content.

## Lifecycle discipline

`updatedAt` never changes for:

- renderer version upgrade (`reference@1 → reference@2`)
- SurfacePolicy version upgrade
- CSS / theme change
- metadata compiler refactor
- LinkGraph recalculation alone
- deployment alone

The lifecycle module has no code path that mutates `ContentDocument`.

## Receipts

Local A3 execution is not a real publication. When run outside a Vercel deploy with
`PUBLIC_ORIGIN_APPROVED=true` and `PUBLIC_INDEXABLE_BUILD=true`, the receipt factory returns
`NOT_ISSUED` with an enumerated list of missing conditions. Tests exercise both paths using
synthetic env fixtures.

## ShortsOS forward-compatibility

CSE does not know `claimCeiling` or `prohibitedClaims` (grep-asserted). A hypothetical
`shortsos_short` contentType validates without a core change and does NOT receive an Article
JSON-LD node by default. ShortsOS integration itself is NOT implemented in A3.

## What A3 does NOT do

- ShortsOS integration, RepOS integration, Native / textos-v0 modifications.
- Automatic backlink writes.
- Any deployment or publication escalation.
- Loosening the fail-closed gates.
